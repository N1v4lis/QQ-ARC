# 冷启动进入界面后的未响应（2026-10-07）

## 原因与修改

默认仪表盘同时读取用量总览和明细。本机有3535个会话文件；此前两条历史读取路径均在Electron主线程同步读盘、解析JSON。计价还逐条调用getConfig，间接反复同步读取账号注册表。一轮12000条记录会读取配置12001次。窗口虽然先显示，随后仍可能被这些工作阻塞。

此前延后30秒预热只能延后后台任务，无法避免仪表盘主动查询触发统计。本次将两条会话解析路径都移入一个按需创建的Worker，主线程只接收精简用量记录；并发相同请求合并，Worker缓存按目录、文件修改时间及大小失效，删除文件清理缓存。空闲Worker不阻止退出，核心停止时终止并拒绝未完成请求；异常后下次请求可重新创建。

每次计价只取一次配置，同次计算按模型和渠道缓存价格。保留原解析器及费用规则，包括旧会话格式、缺少起始时间、缓存token上限、峰谷价格及自定义渠道价格。没有删除历史数据。UI、4秒冷启动动画与2.6秒刷新动画未改。

## 实测与边界

完全退出后重新启动，100ms主线程心跳记录超过40ms的延迟；时间从主入口开始，比较窗口显示后的记录。未清系统磁盘缓存，因此是本机重复启动对照，不代表所有硬件的绝对速度。

| 测量 | 窗口显示 | 显示后最大主线程延迟 | 用量明细响应 |
|---|---:|---:|---:|
| 修改前 | 1779ms | 2387ms | 7473ms |
| Worker第一次 | 1741ms | 66ms | 4674ms |
| Worker复核 | 1915ms | 49ms | 6677ms |

原始事件只保留时长、数量、API路径和生命周期字段：[修改前](post-startup/baseline.jsonl)、[首次优化](post-startup/worker-first.jsonl)、[优化复核](post-startup/worker-verified.jsonl)。两个早期采样未成功连接界面调试上下文，主进程记录有效，不能用于界面线程前后比较。最后一次成功取得界面长任务：去重后67ms和107ms，均发生于4秒动画结束前，后续采样未记录长任务。原始证据保留重复观察记录，采样工具已修正重复收集。

多秒连续主线程阻塞已在两次优化采样中消失，但统计仍要读历史文件，明细约4.7–6.7秒；仪表盘目前等待相关请求一起完成，数据展示尚非瞬时。后台线程会增加独立线程与解析缓存内存，不能将响应改善等同于零CPU或零内存开销。会话目录枚举及汇总仍在主线程，极大数据集需要继续测量。

## 安装、验证与回退

在现有异步启动、SnowLuma启动及插件加载补丁之后执行：

```powershell
node tools/patch-host-usage-responsiveness.mjs
node tools/check-usage-responsiveness.mjs
node tools/restart-agent.mjs --apply
```

安装器复制reader、worker、parser及QQ Agent MIT许可，保存宿主app.js备份，重复执行幂等，写入失败恢复已部署文件。原解析器变化时拒绝安装，需先人工检查口径。重装宿主后需按README顺序重新部署补丁。回退至此次安装生成的app.js.bak-usage-responsive-*，然后重启；无人引用的三个辅助模块可保留。

专项验证：三种价格模式各12000条记录，优化前后费用完全一致，配置读取12001→1；精确记录、旧格式、缺时间、损坏JSON、并发合并、修改文件失效、窗口筛选与退出清理通过。另运行JS语法、异步启动生命周期专项及static四项；不恢复用户停用的38套回归。

需要重新诊断时运行node tools/profile-post-startup.mjs（约45秒采样，加退出时间）。它临时注入计时探针并重启，finally恢复原文件；测完再运行普通重启以清除内存探针及调试端口。只写本地时间与计数，不收集账号或消息正文。
