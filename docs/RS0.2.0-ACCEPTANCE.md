# RS0.2.0 — Resonance — 共鸣 · 第一次理解

RS0.2.0 — Resonance — 共鸣 · 第一次理解
开发分支：RS0.2.0。RS 延续 Rust+Slint 系列命名；实际产品为 Flutter UI + Rust 核心，酒狐继续排除。

目标：恢复全部原有功能的真实执行链路。不能只恢复页面或保存配置，必须完成输入、执行、结果展示、失败处理和持久化。

验收范围：
- 模型与会话：提供商、模型协议、多模态输入、thinking、流式输出、运行取消、工具事件时间线、故障备选和请求计费。
- 数据：会话存档、记忆与成员档案、文档分类检索、导入、模板管理、用量分项和历史价格联动。
- QQ：OneBot、多账号、白名单、禁言、长消息、主动话题、持续话题、表情包和群管理工具。
- 扩展：工具/技能/插件执行、市场获取、显式启用及 Agent/Harness 适配；不把旧 JS 清单误报为可执行插件。
- 系统：SnowLuma 生命周期、GitHub 更新、代理、主题导入导出及制作规范、账户与社区操作。

每项恢复都需要模拟或本地集成验证、UI 联动及明确的异常状态。第三方真实 QQ/模型、未知更新源及兼容性限制如实列出，缺少必要条件时保持待验收，不伪造成功。0.1 的全新空白安装包、打包资源、默认关闭到任务栏规则继续适用。完成本 Milestone 后再创建下一版本分支。

## 实现进度

任务按 [功能矩阵](NATIVE-FEATURE-MATRIX.md) 逐项补齐；本里程碑仍保持开放，未完成项不能随构建成功自动关闭。


### 已恢复并进行模拟验收

- 会话：手动/自动运行统一记录，工具请求/结果/用量时间线，账号隔离取消；OpenAI 兼容流式增量文本和工具参数拼接，JSON 响应代理仍兼容。取消等待模型时不等待完整请求超时，不重试已发生的发送。
- 数据：分类记忆文档、成员档案与会话摘要 CRUD 和搜索，按账号/会话隔离；对应文档参与模型上下文。自定义人设模板新增、更新和确认删除，其他模板保持。
- QQ：超长 Unicode 正文自动拆分，重复分片不会被发送去重误丢；禁言期限保存到账号配置。查询工具、@、图片发送和显式启用的群管理工具通过 OneBot 执行，手动模型测试不执行发送和管理副作用。
- 主题：数据型 .qqtheme 导出/显式导入，字段白名单、背景大小/尺寸限制、密钥与自启字段排除，界面接入。制作规范见 [原生主题规范](THEME-AUTHORING-RS.md)。
- 扩展：用户显式配置的本机可执行 Agent/Harness，参数数组与标准输入、工作目录、输出上限、超时终止 Windows 进程组；配置未启用时拒绝执行。模型委派需要额外开启 delegate_agent 工具。

### 仍在恢复或待真实验收

官方 Claude/Gemini 的增量展示、完整 thinking 与多媒体执行、缓存/思考 Token 和历史价格重算、记忆自动整合与向量、主动话题/持续话题/表情包、旧 JavaScript 插件兼容、完整市场安装发布、多 QQ 注入/自动登录、更新下载安装回滚、全部用户流程人工验收仍未完成。不能把本页的新增接口当成这些全部功能已恢复；Milestone 保持开放。

0.1 的干净安装器和 ZIP 已生成并完成负载校验/独立解包/空白首启验证。0.2 创建了独立分支并继续开发，不关闭旧安装或读取旧用户数据。


SnowLuma 分发边界：本安装包未附带 SnowLuma。OneBot 页面提供官方发行页入口，并支持用户准备的完整 Windows 组件目录（node.exe + index.mjs）；未指定目录时只检测程序旁的 components/snowluma 与 snowluma，不扫描旧安装。未准备时显示可操作的缺失状态，官方更新来源默认 SnowLuma/SnowLuma。随附 EULA 第 5.4 条要求将专有组件并入第三方安装包前取得书面授权，确认范围后再处理随包分发；当前不执行下载、部署或 QQ 登录。
