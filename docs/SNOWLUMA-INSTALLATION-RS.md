# SnowLuma 1.14.22 获取、安装与版本提示

当前 QQAF 固定以 **SnowLuma v1.14.22 / Windows x64 完整包**作为适配目标。没有跟随官网最新版的渠道、定时检查或静默更新。适配目标随 QQAF 版本维护，不等于宣称真实 QQ 登录和收发已在开发机完成验收。

## 用户流程

在 OneBot 页面点击「安装 SnowLuma」：查询固定版本的官方 GitHub Release，选择带 node.exe 的完整包，下载并校验 SHA-256，然后安装。默认位置为 `<QQAF 程序目录>/Snowluma`；允许输入绝对路径，或选择父文件夹。已有配置目录会用于更新，首次安装默认使用程序根目录。安装结束自动保存该账号的组件目录，组件启动与 QQ 登录仍由用户操作。

也可以只下载原包，打开下载文件夹，或继续使用自行准备的组件。下载使用 QQAF 已配置的 HTTP/HTTPS 代理；模型 API Key 不进入下载请求。失败、校验不一致和取消都有明确状态。

## 更新提示

QQAF 启动或切换账号后，仅在本地读取所选组件的 package.json（缺失时尝试本应用安装记录），按数字版本比较当前 SL 和随 QQAF 编译的适配目标。

- 当前版本低于目标：显示更新提示，可前往 OneBot 页面确认安装，也可稍后处理。
- 版本相同：不提示更新。
- 用户已使用更高版本：不自动降级。
- 未安装或版本无法识别：显示缺失/未知状态，不伪造版本。

本地检查不访问 GitHub、不下载、不启动组件。每个账号在本次应用会话仅检查一次，安装完成后重新读取。未来 QQAF 提高目标版本时，沿用这条链路提示用户，而不是要求用户持续追随 SnowLuma 的发布节奏。

维护者需要同时更新 `native/resources/snowluma-compatibility.json` 和 `snow_downloads.rs` 的 SUPPORTED_TAG。清单保存官方文件名、字节数和 SHA-256；官网同标签资产发生变化时会拒绝使用未验收的新字节。真实兼容验收完成后再补 validated 记录。

## 安装边界与恢复

下载流式写入独立账号数据目录，不把整个发行包载入内存。只有与官方元数据及内置适配记录一致的文件才保留为可用原包。ZIP 解压发生在所选目录旁的独立暂存目录，拒绝越界、符号链接、Windows 保留名和重复路径；限制文件数与解压总大小。

更新时保留 config、data、logs、cache、用户文件，并将原目录完整保留为备份。未准备完成不替换原目录，提交失败尝试恢复；运行中或被占用的组件需先停止。非空且不属于 SnowLuma 的目录拒绝覆盖。多个账号不能同时更新同一个安装位置。官方脚本、运行时、原生组件和包内 EULA/隐私说明保持原样。

QQAF 安装包不捆绑 SnowLuma。干净构建只复制明确的 Flutter 运行文件、插件 DLL 和资源，排除开发时装在程序旁的 SnowLuma、配置、日志和备份，避免把本机内容带入新安装包。

## 验证范围

模拟测试覆盖完整包选择、固定版本与来源/摘要校验、流式写入、取消、异常 ZIP、配置保留、备份、无关目录保护、数字版本比较、首次本地提示和点击安装。另已下载官方 v1.14.22 原包核对目录结构及 SHA-256。没有执行该官方包，也没有启动或连接真实 QQ；真实 QQ 接入仍需要用户验收。
