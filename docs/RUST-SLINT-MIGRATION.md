# Flutter＋Rust 核心迁移与酒狐方案评估

日期：2026-10-09。开发分支保留原名 `Rust+Slint`；当前主界面方向已调整为 Flutter，业务核心为 Rust。旧架构归档：`v0.4.5a`。

酒狐后续实现仍在考量：Slint 承载并接入原生 3D，或直接原生 3D 合成到 Flutter。未选定、未实现完整模型渲染；两条候选均要求开关默认关闭，没有可用硬件 GPU 时禁止启用。README 保留与 main 相同的归档警告，在正文另行说明最新分支方向。

旧架构开发无限期暂停，恢复时间待定。若迁移可行性验证通过，停止旧架构后续开发；目前不宣布迁移成功。README 公告同步到 main，之后迁移代码与文档均在 Rust+Slint 分支提交及推送。

## 目标与边界

- Rust 负责业务、存储、网络和任务调度，Flutter 负责原生桌面 UI；目标运行时不依赖 Node、Electron 或 WebView。
- QQ 客户端由用户提供；QQ 接入仅针对 OneBot / SnowLuma。不把安装 QQ 纳入 QQAF 安装包。
- Minecraft 主题提供酒狐开关，首次默认关闭。必须检测到可用硬件 GPU（包含核显）并成功创建所需渲染设备；CPU 软件适配器、失败或无法确认硬件能力时禁用。运行中设备丢失应停止渲染，保持业务继续运行。
- 普通界面可使用 Slint 软件渲染。VPS 没有硬件 GPU 不应阻止聊天业务，但不启用酒狐；没有桌面环境的后台运行模式另行实现。
- 原客户端和原账号数据不作为实验运行目录。迁移前备份、导入兼容、行为一致性及故障回退均需验收。

## 首轮代码（进行中，尚未完成验收）

`native/` 是独立 Cargo 项目。Slint 编译界面采用自绘标题栏，原型主题切换与设置保存在独立数据库。Rust AccountStore 已实现每账号 SQLite WAL、正文 TEXT 持久化、增量追加及按消息 ID 游标分页。这里只建立最小存储接口，尚未复刻旧库所有字段、扩展 BLOB 和上下文策略。

GPU 检测在线程中枚举设备，仅接受确认的独显或核显类型，并实际尝试创建 wgpu Device；普通界面使用软件渲染。该检查验证基础设备创建，未来酒狐管线仍需要真实模型、骨骼动画、透明合成与设备丢失测试。原生 3D 未完成前开关保持禁用，不用静态占位冒充酒狐迁移成功。

OneBot 模块目前解析消息事件、按 self_id 标识账号、按 group_id/user_id 标识聊天，并构造只读 get_version_info 请求。网络连接、鉴权、重连、媒体和 CQ 消息分段解析尚未实现，原型不会向 QQ 或模型 API 发请求。

旧库中的 V8 二进制不是 Rust 可直接使用的通用序列化格式。后续需要单独设计受控迁移工具及稳定的跨语言扩展格式，不能直接将旧数据库接到此原型，也不宣称无损迁移完成。

## 可行性验收顺序

1. 原生界面可构建、运行；自绘窗口、中文显示、DPI、布局、键盘与无 GPU 环境验证。
2. 独立账号存储与迁移：并发写、分页、异常 Unicode、媒体/引用、备份及历史用量一致性。
3. OneBot / SnowLuma：鉴权、消息接收与发送、断线重连、多账号隔离。
4. 模型 API：流式响应、取消、代理、工具调用、图片/视频配置及计价一致性。
5. 酒狐：现有 GLB 骨骼动画与材质、Slint 内嵌透明合成、动作互动、GPU 能力门控和设备丢失恢复。
6. 人设、主题、插件、技能和市场：原数据契约及全部核心行为迁移。现有 JS 插件不可未经设计直接视为 Rust 可运行。
7. 干净 Windows 安装验收、运行依赖打包、许可证声明、更新与卸载；实测安装体积、空闲占用、启动耗时和持续消息负载后再判断是否替代旧架构。

Slint 参考：[Rust 文档](https://docs.slint.dev/latest/docs/rust/slint/)、[渲染后端](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/)。GPU 参考：[wgpu 文档](https://docs.rs/wgpu/latest/wgpu/)。构建依赖不是用户运行时安装要求。
