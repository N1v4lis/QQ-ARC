# 0.4.5a — 架构迁移前归档

发布日期：2026-10-09。

本版归档当前可运行的 Electron／Node.js／Three.js 实现，作为后续架构迁移前的参考基线。保留 0.4.5 的 API 与搜索、官方计价、人设、主题和酒狐功能，主要新增多账号原生 SQL 存储底层。

## 存储与运行链路

- 每个 QQ 账号拥有独立 SQLite WAL 数据库与写入 Worker；同账号群聊、私聊串行提交，不同账号可并行写入各自的库。消息追加、修改、撤回、已读和删除按行处理，避免反复重写完整历史文件。
- 正常消息、存档、记忆和用量缓存不再封装为 JSON 文档，也不做 Base64 存储传输。正文、发送者、时间、媒体、引用、轮次及 Token 计数使用原生列和关联表；复杂响应和未知扩展字段使用 V8 二进制，较长历史提示词按字符串压缩保存。
- 聊天列表读取元数据，历史消息 SQL 分页；会话索引只读摘要，用量读取独立计数列，减少解析完整提示词与原始响应的开销。
- 使用 FIFO 队列、批量事务、写入积压限制及退出 flush。写入调用返回表示入队，提交确认之后才表示持久化；强制终止仍可能丢失未提交的队列。
- 增加存储安装、宿主补丁、主动导出、实际迁移核验和可复现基准工具。部署版本由 VERSION 同步为 0.4.5a。

## 兼容与数据保护

官方旧版 JSON 导入单独实现；早期 v1 库升级前生成一致性快照，原 JSON 与辅助文件保留备份。异常 Unicode、媒体、引用、扩展字段及用量解析语义均有针对性验证。主动导出继续提供 JSON；配置、HTTP 与 OneBot 协议保持原格式。

Release 不包含用户数据库、聊天内容、账号配置、密钥、机器环境副本、node_modules 或编译后的本地驱动。存储运行时由锁定依赖与安装工具准备，Electron 驱动下载带摘要校验。源码包不是完整安装器，部署工具的环境配置需要在目标机器核对。

## 性能与验证

三次合成基准的中位数：600 组追加与已读操作由约 5323 ms 降至 78 ms；首屏分页由约 6.24 ms 降至 3.29 ms。测试中的完整历史冷对象读取由约 57 ms 增至 198 ms，进程峰值 RSS 由约 85 MiB 增至 180 MiB，初始化也增加。这些是测试进程与 Worker 的结果，不能推导为整个客户端的固定内存收益；首屏测试的操作系统磁盘缓存已经预热。

实际迁移核验：两个账号、3822 条升级记录逐条一致，SQLite quick_check 通过。当前数据库约 192.26 MiB，原 JSON 约 330.06 MiB；原 JSON、v1 快照和辅助备份仍占用磁盘，且原生库比早期压缩 JSON 的 v1 库更大。保留备份时不能宣称已经释放这些空间。

验证范围：存储专项、多账号并发与重开、宿主实际调用兼容、禁用正常存储 JSON 转换、旧数据升级与导出、用量计数一致性，以及默认四项静态检查和相关 JavaScript 语法检查。未重新运行已停用的酒狐完整互动套件。

## 后续范围

Rust、Slint、Tauri 与 Qt 的讨论属于方案评估，本版尚未进行 UI 或后端语言迁移。运行中部分 ChatStore 缓存仍会加载完整会话，部分读取同步等待 Worker；低内存、完全异步上下文和减少模型 Token 的设计目标尚未全部完成。SnowLuma 更新检测、代理、主题打包及多 QQ 自动登录方案也不因本次归档视为已实现。

详细实现、限制与基准见 [账号存储说明](../ACCOUNT-STORAGE.md)；上一版界面与功能改动见 [0.4.5 发布说明](0.4.5.md)。
