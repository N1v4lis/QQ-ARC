# 仪表盘加载优化（2026-10-07）

用户要求后端一起优化，保留前端表现方式；最新动画时长为冷启动2秒、刷新1秒。本次保留信息卡、图表、配色、固定列布局及导航目标，不引入前端框架或图表库。

## 数据架构

此前五个请求Promise.all全部完成后才显示整页。用量stats已带会话汇总，dashboard还请求不带筛选的breakdown，后者全量解析3535个历史会话，重复工作约4.7–6.7秒。

新增只读GET /api/dashboard/usage?range=7，一次buildUsageStats同时提供stats和breakdown形状的排行；复用既有按天快照及今日增量解析。仪表盘不再调用全量breakdown，其他页面的交叉下钻与明细接口保留。排行与信息卡采用相同快照口径；历史快照固定生成时价格的既有取舍没有改变，不能将其声称为历史会话逐条实时重算结果。

buildUsageStats外围增加进程内缓存：最多8个结果、有效期3秒，相同键的在途请求合并，返回副本防止调用者污染。键包含数据目录、当前账号、区间、自然日、会话目录签名和API价格配置。新增/删除、切账号、改配置、跨日隔离；3秒到期后重新进入原统计路径；底层历史快照对原地改写及改价的既有失效规则不在本轮改变。fresh=1跳过已完成缓存，仍合并正在计算的同键任务；失败不缓存。缓存不会绕过已有按天快照规则，也没有持久化账号或配置数据。

前端并行请求共享统计、运行状态、会话及账号四种数据，各自完成就填对应区域。先显示现有完整卡片结构，未知数字用“— / 加载中”，失败明确提示，避免虚假的零、未连接或运行中。局部替换数据区域，保留顶栏焦点、Beta观察器和未变卡片；点击与键盘导航改为一次事件委托。

每个区间/账号的完整成功结果仅保存在本页面内存30秒，重访先显示并重新请求；手动刷新及区间切换不复用快照。刷新序号、区间、活动页签和容器身份阻止晚到旧请求覆盖新结果；账号切换继续由原机制整页重载。
