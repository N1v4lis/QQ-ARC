## 一、项目由来的那句总纲

用户最早提出的目标是三件事叠在一起：

> "在现有 QQ Agent 新增功能保持可用的情况下，包括原生自带的插件广场等等 / 以 Codex 或者
> DeepSeekHarness 的 UI 为基底，重构 UI / 要求不使用 Windows 自带的任务栏（关闭，最小化）/
> 带有一定程度的动效"

后来又补了最要紧的一句约束：

> "最重要的是，在新的文件夹重构 UI，再移植功能，不影响现有运行"

**由此推出三条不可动摇的工程约束：**

1. **不许影响现有运行** —— 老控制台 `resources\app\ui\` 一个字节都不许改。
   新 UI 放 `ui-next/`，靠 `QQ_AGENT_UI_DIR` 切换，随时能退回去。
   本项目的开发服务器（`tools/dev-server.mjs`）就是为这条存在的：从工作区伺服、`/api/*` 转发到正在跑的实例，
   于是"改界面"和"用户正在用的界面"彻底分开。
2. **功能必须仍然可用** —— 原生入口、插件广场、市场、SnowLuma、记忆/存档/技能……
   重写外壳不能把这些弄丢。考核口径见 `TESTING.md` 里的 `check-dom-contract` / `check-markets` 等套件。
3. **无边框窗口 + 自绘标题栏** —— 去掉原生标题栏和右上角三个按钮，由页面 `.q-titlebar` 自绘，
   主进程补"三个动作 + 状态回推"。交付与验证见 `docs/electron-shell.md`。

## 二、用户明确纠正过的地方（这些最容易做反）

### 2.1 主题亮度：**两档**，不要"跟随系统"

- 中途我做成过"自动 / 亮色 / 暗色"三档，用户要求改回：

  > "亮暗联动不是要改成跟随系统，而是直接亮色和暗色切换"

- 现在的实现：`cycleTheme()` 在 `light` ↔ `dark` 之间**直接翻转**，UI 里**没有** auto 入口。
  旧的 `auto` 偏好会被 `shownPref` 映射成合法值，但**不要再把它加回界面**。

### 2.2 MC 主题：字体标点、音效用途、开关音，三件都被专门纠正过

- **字体**：`[苦力怕论坛]Minecraft(同时支持中英文).ttf` 渲染 ASCII 标点是坏的
  （`:` 变 `u`、`(` 变 `C`、`/` 变 `i`、`¥` 变成方块），但汉字和全角标点正常。
  现在的做法是**双字体链 + `unicode-range`**：拉丁字体在前、只管 ASCII 与全角标点，
  中文那面只吃 `U+3400-4DBF, U+4E00-9FFF, U+F900-FAFF`。
  **顺序是承重的**，别调换；改完跑 `check-font-chain.mjs`（逐字形比对 19 个字符）。
- **音效默认值**：用户指定"菜单按钮音用 `UI\Click.wav`"、"拉杆也改成菜单按钮"，
  并要求**删掉**音符盒 / 拉杆 / 木质 / 石质那几个合成音（**文件与配方一起删，不打包**）。
  偏读取有迁移映射（`note/lever/wood/stone/pistonSynth → menu`），否则老配置会读出**空下拉框**。
- **开关音的边界**：原话"用于开关的不用于按钮和点击"。后来信标从点击音里整个拿掉，
  且 `clickSfx` 与 `toggleSfx` 的默认值都变成 `menu` ——
  所以现在的断言口径是"**除故意共用的 `menu` 外，用途候选不许重叠**"，不是"完全不许重叠"。
- **拉杆音**：用户说"听着很杂" → 去 wobble、120ms→55ms、10.4KB→4.8KB。
  **不要**再往上加混响/合成层。

### 2.3 开关（`.switch`）在 MC 皮肤下必须长成**拉杆**

> "所有开关都应该用二级设置中的小拉杆形式（包括动效），如图一所示的开关仍然为原版，极度违和"

MC 的拉杆是画在 `input[type=checkbox]` **自身**（`::before` 石座 + `::after` 木杆）上的；
而设置页那批开关用的是 `.switch` 组件，它把复选框**视觉隐藏**了 ——
所以拉杆根本画不出来，落回"胶囊 + 圆点"。
修法见 `THEME-SYSTEM.md`；要点是**只平移不旋转**（旋转会把握把甩出轨道、盖住文字），
且选择器必须带 `html[data-skin=…]` 前缀才压得过 `40-market.css` 的 `.switch .track`。

### 2.4 取景与样式这类"看着能自由发挥"的地方，都有过明确表态

- **列表 / 卡片位置不许游走**：仪表盘卡片曾用 `auto-fit`，卡片数量一变位置就变；
  用户不接受，已改成**显式列数** `repeat(5)` / `repeat(3)`（900px 以下 3 列、620px 以下 2 列）。
- **滑条默认不开启音效**，但用户要能自选 —— 所以 `sliderSfx` 默认 `'off'` 而下拉里给候选。
- **撤销按钮不许改变页面高度**，且位置要贴区块标题：
  > "撤销本次设置不应该动页面内容高度，并且它的位置应该聊天设置文字的旁边"

### 2.5 顶栏配色：这条被**两版需求来回拉过**，改之前先看这段

| 时间 | 要求 | 当时做法 |
|---|---|---|
| 2026-10-04 | 用户反馈"不是每一个导航栏的颜色都是连续的" → 要**无痕** | 标题栏 / 功能条 / 侧栏 / 内容区统一到 `--q-bg-base`，横向接缝靠同色消除 |
| 2026-10-06 | "任务栏的底色为什么和主体内容的颜色一致，应该和导航栏的颜色一致" | 新增独立令牌 `--q-bg-titlebar`，MC 皮肤指向 `--q-bg-sidebar` |

**两者都对，冲突来自"哪个算导航栏"**。所以现在把这件事做成**令牌可调**：
`--q-bg-titlebar`（缺省回落 `--q-bg-base`）。要再调只改 `32-theme.css` 里的覆写，**不要**去动
`02-titlebar.css` 那条背景声明。注意暗色下 `--q-bg-sidebar` 与 `--q-bg-base` 差 6 级明度，
一旦混用会出现**横贯整窗的色差线**（`check-seamless-pixels.mjs` 就是守这个的）。

## 三、已被否决 / 已回滚的做法（别再试一遍）

## 五、待办与未决（唯一需要向用户确认的清单）

当前**没有**已知的、待用户拍板的阻塞项；回归全绿。以下是留给接手的观察点：

0. **宿主插件会注入部署界面，而且会被部署冲掉**（最容易掉进去的坑，先说这条）。
   `plugins/theme-mode`（已安装、是活的）会往**部署的** `ui-next/index.html` 注入
   `<script defer src="/theme-switcher.js"></script>`，并同时产出 `theme-mode-status.json`。
   而 `apply-ui --apply` 是整目录镜像、工作区没有这一行 → **每次部署都会移除注入**。
   插件下次自检会补回来；若部署后主题入口消失，让插件重跑一次自检即可。

   关于它到底是"可用功能"还是"残留"，**已实测确认**：
   `theme-switcher.js` 只在 `.skill-modal`（技能弹窗，标识含 `theme-mode`）内部注入 UI，
   而**新 UI 没有这个弹窗** → 它加载成功、HTTP 200、控制台干净，但**不产生任何可见变化**。
   所以它是**无操作的空转**，不是坏掉的功能。**别去"修"它**，也别把它抄进工作区源码
   （抄进去就等于把插件的职责拿到本项目里，插件再注入一次还会重复）。
   守卫：`tools/check-plugin-inject.mjs`（环境不具备时自动跳过，不会误红）。
   > 插件自己的状态文件会报 `missing: ["index.html 未注入任何主题"]` ——
   > 那是它的检测只匹配**主题脚本名**、不认识切换器注入形式，属插件侧误报。

1. **顶栏配色是可调项**（§2.5）。如果用户又觉得不合适，改 `32-theme.css` 一行即可，不要重构。
2. **酒狐是否还要回来**：如果用户改主意，先删 `check-fox-removed.mjs` 的注册再动手，
   否则回归会一直红；资产用 `convert-ysm-wine-fox.mjs` 重新生成。
   注意那次的模型 id 是 `wine-fox`（不是更早的 `maid`/`magic`），manifest 里带
   `source` 与 `license`（CC BY-NC-SA 4.0）—— **署名和许可是必须保留的**。
3. **机器内存是硬约束**：15.7 GB 总内存、跑回归时常只剩 2.5~4 GB。
   软件光栅化的东西（已随酒狐一起删除）曾经把应用拖到 `AppHangTransient` 而整个进程消失。
   现在没有这类重负载了，但**别再引入同步的重计算**。
4. `src/app.js` 的 MIME 补丁在**重装 QQ Agent 后会丢**，需重跑 `patch-host-mime.mjs`。

## 六、验证纪律（用户没明说，但是这个项目的生存线）

1. **不许把"看起来对"当验收**。这个项目里"看着正常、其实一直错着"的 bug 特别多
   （见 `PITFALLS.md`）。每条修复都要能给出**可复现的数值或像素**证据。
2. **断言不许写死当前状态**。曾有一条断言写"恰好 6 个音效"，素材扩到 15 个后它必然失败 ——
   而这会**阻止**后续加素材。改成"从运行时取清单 + 判全部可解码"。
3. **等待条件必须覆盖随后真正读取的元素**。只等 A 就去读 B 是固定套路，
   已造成多次假失败（详见 `PITFALLS.md` 的"假失败三连"）。
4. **改完必须走完部署四步**，再跑全量回归；只跑单个套件不算完成。
