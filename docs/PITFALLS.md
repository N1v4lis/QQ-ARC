# 踩坑速查（症状 → 根因 → 修法）

> 出怪问题时**先翻这里**。每条都是真实踩过的，按"症状"分组，方便照症状找。

---

## A. 改了代码但界面没变化

### A1. 少跑了部署步骤

**症状**：改了 `app/ui/` 下任何文件，重启后界面毫无变化。
**根因**：工作区 ≠ 部署目录。QQ Agent 读的是 `resources/app/ui-next/`。
**修法**：走完 `DEVELOPMENT.md` §一 的四步。
**自查**：`node tools/which-target.mjs`，或看 HTTP 响应里是否含 `q-titlebar`。

### A2. 伺服的是老控制台

**症状**：界面是旧版，但你的改动确实部署了。
**根因**：`applyUiDirDefault()` 的三级选择落到 `ui/` 了。
**修法**：确认 `ui-next/index.html` 存在；或显式设环境变量 `QQ_AGENT_UI_DIR`。

### A3. 把改动写进了 `ui/`

**症状**：改了半天没效果，后来发现在改老控制台。
**根因**：`apply-ui.mjs` 只镜像 `ui-next/`，**从不碰 `ui/`**（这是刻意的回退保障）。
**修法**：改工作区 `app/ui/`。`ui/` 是禁区。

### A4. 某个插件/脚本写死了 UI 目录

**症状**：插件"自检通过、状态文件写出、`index.html` 也改了，界面却零变化"。
**根因**：它把 `path.join(ROOT,'ui')` 写死，而那个目录**根本没人看**。
**修法**：凡是要往界面注入东西的插件/脚本，都必须跟随 `applyUiDirDefault()` 那套三级逻辑。

## B. 页面报错 / 静默失效

### B1. CSP 拒绝了那段内联脚本

**症状**：主题预置"好像没生效"，控制台有一条 CSP 报错。
**根因**：内联脚本的 sha256 变了，而 hash 契约没同步（三处要一致）。
**修法**：`node tools/csp-hash.mjs --write`。
**为什么用 sha256 而不是 `'unsafe-inline'`**：后者会让**任何** `innerHTML` 注入都能执行内联代码。

### B2. `import()` 报 "Failed to fetch dynamically imported module"，而 `fetch()` 同一 URL 是 200

**症状**：动态 import 失败，但把 URL 贴到地址栏/用 fetch 取又是 200 —— 只看网络面板看不出来。
**根因**：`src/app.js` 的静态服务器 MIME 表**没有 `.mjs`**，落到 `application/octet-stream`；
浏览器按规范拒绝把非 JavaScript MIME 的模块当 ES 模块加载。
**修法**：`node tools/patch-host-mime.mjs`（幂等，同时补 `.ttf/.otf/.woff*/.wav`）。
⚠️ **重装 QQ Agent 后必须重跑** —— 那个文件会被覆盖回原样。

### B3. 页面里调 `switchTab` / `openSettingsSection` 报 ReferenceError

**症状**：探针里 `page.eval('switchTab("settings")')` 没反应；
若外面套了 `try/catch`，则**完全静默** —— 看起来像"点了设置页但什么都没发生"。
**根因**：`$` / `$$` / `api` / `state` / `switchTab` 都在**模块作用域**里，**不是 `window` 属性**。
**修法**：模拟用户操作就**点真实元素**：

```js
page.eval(`(() => { document.querySelector('#tabs .tab[data-tab="settings"]').click(); return 1; })()`)
```

**教训**：`try/catch` 吞异常会让"没执行"伪装成"没效果"，在这个项目里耗掉过一整轮。

### B4. 模板字符串的注释里出现反引号

**症状**：`node --check` 报 `missing ) after argument list`。
**根因**：反引号提前结束了模板字符串。
**修法**：注释里不要写反引号（用「」或普通引号）。已就地标注警告的文件：
`06-settings-render.js`、`14-theme-section.js`。同类还有块注释里写 `*/`（会提前闭合）。

## C. CSS 不生效

### C1. 旧皮肤赢过新规则

**症状**：新写的 `.mcard{display:grid}` 不生效，实际是 flex，而源码上毫无破绽（新规则确实在后面）。
**根因**：CSS 层叠里**未分层样式 > 任何分层样式**。
而 `@layer legacy;` 只是**声明一个层**，并不会把样式表放进层 —— 旧皮肤仍是未分层的，所以它赢。
**修法**：只有 `@import url(...) layer(<名字>)` 能把**整张外部样式表**放进层。
当前实现在 `styles/99-legacy-layer.css`（只含这一条 import）。
**完整说明**：`styles/99-legacy-layer.css` 顶部 —— 本项目最值钱的一段注释。

### C2. 覆盖组件外观没生效

**症状**：写了 `.switch .track { ... }` 但完全没有效果。
**根因**：`40-market.css` 里已有同名规则，特指度 (0,2,0)。
**修法**：带皮肤前缀提特指度：`html[data-skin='minecraft'] .switch .track { ... }`。

### C3. 旧皮肤里有未分层的 ID 选择器

**症状**：类选择器的新规则压不过旧皮肤。
**根因**：`#tabs` / `#topbar` / `#layout` 这些 ID 选择器特指度天然更高。
**修法**：新规则也带上同样的 ID 前缀（见 `02-titlebar.css` / `03-sidebar.css` 的说明）。

### C4. CSS 变量"未定义"是**空**，不是继承

**症状**：切到某个皮肤后，某处的颜色/间距变成奇怪的值或直接消失。
**根因**：新令牌只在默认皮肤里定义了，MC 皮肤没给。
**修法**：新增 `--q-*` 令牌时**两处都要给**（`00-tokens.css` 与 `32-theme.css`）。

### C5. 用 `getComputedStyle` 读 `calc()` 算的变量

**症状**：`getComputedStyle(el).getPropertyValue('--mc-mask')` 拿到 `calc(1 - var(--x))` 这种表达式，不是数值。
**根因**：自定义属性不会被计算成最终值。
**修法**：在 JS 里自己按数值算，别指望浏览器帮你解。

## D. 布局 / 对齐

### D1. 同一行的输入框宽窄不一、上下两行起点错开

**症状**：`.field-row` 里几个「标题 + 输入框」的块各占一块，右边参差不齐。
**根因**：`.field-row` 是 `flex + flex-wrap`，而 `.field` 的基准尺寸取 **min-content** ——
由标签里**最长的那个词**决定（例如"禁言时长（分钟，0 = 直到手动解除）"）。
**修法**：

```css
.field-row:has(> .field) { display: grid; grid-auto-flow: column; grid-auto-columns: 1fr; align-items: start; }
.field-row:has(> .field) > .field { min-width: 0; }   /* ← 少了这句 1fr 会被长标签撑开 */
```

对 2 列和 3 列的行都成立，不用为每行写死列数。窄屏（≤760px）退回单列。

### D2. 某个元素一出现就把页面内容顶下去

**症状**：动态插入的按钮/提示一出现，下面的内容整体下移（高度跳动）。
**根因**：它被当成**独立块级行**插进了容器（如 `form.prepend(btn)`）。
**修法**：插到目标标题元素**内部**，把标题变成 `display:flex` 的"标题行"，
并把新元素的高度压到 ≤ 标题行高 —— 这样高度增量是 0。
参考实现：`#settings-form h3.settings-h3-row` + `.settings-undo-btn`。

### D3. 量元素尺寸时拿到 0 或量不到

**症状**：断言说"可见 0 个"，但你明明看到它们在屏幕上。
**根因**：三种可能 ——
① 元素在**折叠卡**里（`display:none`）；
② 元素在**视口外**（`getBoundingClientRect()` 仍返回值，但内容可能还没渲染）；
③ 你等的是 A，B 还没渲染（见 E1）。
**修法**：先展开所有折叠卡再量；需要时**边滚边量**；等待条件覆盖要读的元素。

### D4. 把"色块输入框"当成文本输入框统计

**症状**：一个页面报出 60 个"文本框"，其实全是配色色块。
**根因**：选择器 `input:not([type])` 之类把 `input[type=color]` 也捞进来了。
**修法**：显式列出真正的文本类型（`text/number/url/password/search`），
并排除 `color` 与 `range`。

## E. 测试假失败（最费时间的一类）

### E1. "只等 A 就去读 B"

**症状**：单独跑绿、批量跑随机红；或报 `getComputedStyle(null)` / `null.click()` 这类错。
**根因**：等待条件只覆盖了 A，随后却读 B。
**修法**：等**所有**后续要读的元素同时就位。

### E2. 断言写死了"当前状态"

**症状**：加了一个素材/动画后，某条断言必然失败。
**根因**：断言写的是数量或方向，而不是关系。
**修法**：判"关系"（组间 > 组内）、判"明显多于被裁剪过的集合"、
从运行时取清单再判性质（如"全部可解码"）。
⚠️ 写死数量最坏的后果不是"偶尔红"，而是**阻止后续扩展** —— 为了让它绿就得删素材。

### E3. 用整卡文本判断"某分组还在不在"

**症状**：分组明明删了，断言仍说它在。
**根因**：卡头副标题本身会写"音效 · 背景 · 字体"这类字样。
**修法**：改用 `.pz-group-title` 的分组标题列表。

### E4. 布尔默认值的陷阱

**症状**：某个功能开关"看起来一直是死的"，改了没反应。
**根因**：`if (patch.showDecor != null)` —— 默认值是 `false` 时 `false != null` 为 `true`，
但语义上你以为它判断的是"这个键在不在"。
**修法**：用 `k in patch` 判断键是否存在。

### E5. 守卫型测试把自己判进去

**症状**：一条守卫测试**永远红**，而且看起来逻辑没问题。
**根因**：它用文件名模式匹配整个回归清单，而**它自己也注册在里面、名字也含那个模式**。
**修法**：判据改成"除本守卫外不应再有别的同类套件"。

### E6. 瞬态失败被当成产品失败

**症状**：`page.screenshot` 偶发超时，但应用在线、界面正常。
**修法**：区分"工具瞬态"与"产品问题"——捕获并**打印**，不判失败。

### E7. 页面内轮询把调试通道堵死

**症状**：`CDP 超时：Runtime.evaluate`，最后打印的日志停在某条断言，真实卡点却在它后面。
**根因**：在**页面主线程**里 `while (Date.now() - t0 < 90000)` 空转；
`awaitPromise` 的 CDP 调用只能干等，最终以超时失败。
**修法**：页面内轮询**必须有短超时**，绝不阻塞到把调试通道拖挂。
另外给 `cdp.eval` 加了"超时时打印出错的表达式" —— 这条改动让原本查了很久的问题**一次定位**。

## F. 运行环境 / 进程

### F1. 应用"整个消失"，日志里什么都没有

**症状**：回归跑到中途 QQ Agent 进程没了；Windows 事件日志显示 `AppHangTransient`；
应用自己的日志无任何异常栈。
**根因**：**内存耗尽**。本机 15.7 GB 总量，跑回归时常只剩 2.5~4 GB；
历史上引入过**同步**软件光栅化的功能（在主线程按像素×面数计算），把主线程占满后被系统回收。
**修法**：① 别再引入同步重计算；② 提高分辨率/帧率前先量单帧耗时；
③ 回归中途挂了先 `restart-agent --apply` 拉起来，再判断是套件问题还是资源问题。

### F2. 重启后"双击没反应"，日志空白

**症状**：杀进程后重启，窗口起不来，日志里什么都没有。
**根因**：进程没关干净 → 新实例被**单实例锁**挡掉 → `main.js` 拿不到锁就**静默 quit**。
**修法**：用 `restart-agent.mjs --apply`（杀干净 → 逐秒复核进程真的没了 → 启动 → 验证）。

### F3. 发布物里混进了自己的临时文件

**症状**：部署目录里出现 `*.bak-xxx`、探针脚本之类。
**根因**：`apply-ui.mjs` 是**整目录镜像**，工作区里有什么就拷什么。
**修法**：改完清掉临时文件再 `--apply`。

### F4. CDP 临时 profile 堆积

**症状**：`%TEMP%\qqa-cdp-*` 目录越来越多。
**根因**：`cdp.mjs` 会杀测试浏览器并删临时 profile，但 `child.kill()` 是异步的，
Edge 子进程可能活得比它久，导致删除失败。
**修法**：定期手工清理 `%TEMP%\qqa-cdp-*`（确认没有正在跑的测试）。

## G. 数据 / 状态

### G1. `state.config` 是 null，设置页整块变成一行红字

**症状**：`设置页渲染失败：Cannot read properties of null (reading 'api')`。
**根因**：`state.config` 要等 `loadSettings()` 里 `Promise.all([7 个请求])` **全部完成**才赋值；
而 `renderApiSection` / `renderToolsSection` 是**直接解引用** `c.api` / `c.tools` 的
（全设置页只有这两处没有 `?.`）。配置没到就渲染 → 抛错 → 被外层 catch 成"渲染失败"。
**修法**：`renderSettings` 里先判配置是否存在；缺就渲染**加载态**并**有界自动重试**
（最多 10 次 × 700 ms），成功后恢复正常渲染。最坏是"多转一会儿"，不再是"一片报错"。
`renderToolsSection` 另加 `(c || {})` 兜底。

### G2. 动态插入的元素"出现过一次就再也不出现"

**症状**：撤销按钮第一次改设置时出现，之后无论怎么改都不出现。
**根因**：`renderSettings()` 会**整体重建表单的 innerHTML**，把按钮丢掉，
但保存按钮引用的变量**仍指向已脱离文档的旧元素**，所以 `if (btn) return` 永远为真。
**修法**：判据改成 `btn.isConnected`（在不在文档里），而不是"变过没"。
**通用教训**：**长生命周期引用 + innerHTML 重建** 的组合必须用 `isConnected` 兜底。

### G3. 老配置读出来是"空下拉框"

**症状**：音效下拉一片空白，明明素材都在。
**根因**：偏好键改过名（`note/lever/wood/stone/pistonSynth` → `menu`），老值不在候选里。
**修法**：读取偏好时加**迁移映射**。新增/改名偏好键时都要想一遍这件事。

### G4. 数据源换了但断言没跟着换

**症状**：换数据源后一堆断言红，但功能其实是好的。
**根因**：断言写的是旧数据源的特征（动画条数、模型 id）。
**修法**：断言改成"性质"而非"具体值"（见 E2）。
